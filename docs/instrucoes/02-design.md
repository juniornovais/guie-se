# DESIGN DO PRODUTO — PLATAFORMA DE ESTUDOS

Atue como Product Designer e especialista em UX/UI de produtos digitais.

Quero criar uma plataforma pessoal de estudos com identidade visual própria, moderna e diferenciada.

O produto será baseado em um roadmap técnico de desenvolvimento Backend Java, dividido em seis grandes etapas.

Não quero um dashboard administrativo genérico. Quero uma experiência que transmita a sensação de percorrer uma jornada de aprendizado e evolução profissional.

## 1. Direção visual

Desenvolva uma identidade visual que combine:

- Plataforma de aprendizado.
- Mapa de progressão.
- Ambiente de desenvolvimento.
- Sistema de evolução pessoal.

A interface deve ser moderna, minimalista, elegante e muito bem organizada.

Busque referências conceituais em plataformas como Linear, Notion, roadmap.sh e GitHub, mas não copie seus layouts.

Crie uma identidade própria.

## 2. Página inicial

A página inicial deve responder imediatamente:

- Onde estou no roadmap?
- O que estou estudando?
- Qual foi meu último estudo?
- O que devo estudar agora?
- Quais desafios estão pendentes?
- Quanto já evoluí?

Elementos:

- Progresso geral.
- Etapa atual.
- Módulo atual.
- Último tópico acessado.
- Botão "Continuar estudando".
- Próximo tópico recomendado.
- Atividades recentes.
- Desafios pendentes.

Priorize a continuidade dos estudos.

## 3. Página do roadmap

Essa é a principal experiência visual do produto.

Quero visualizar as seis etapas:

01. Fundamentos.
02. LeetCode.
03. Backend.
04. Java Backend.
05. Sistemas Distribuídos.
06. System Design.

Cada etapa deve possuir módulos e cada módulo deve apresentar seus tópicos.

Explore um mapa de progressão interativo, com:
- Etapas visualmente distintas.
- Módulos agrupados.
- Tópicos conectados quando houver pré-requisitos.
- Indicadores de progresso.
- Estados de conclusão.
- Estados de estudo atual.
- Próximos passos.

Quero conseguir visualizar a evolução da minha jornada sem precisar navegar por uma lista interminável.

O roadmap deve continuar utilizável mesmo com centenas de tópicos e desafios.

## 4. Página do módulo

Ao entrar em um módulo, quero encontrar:

- Descrição.
- Objetivos.
- Progresso.
- Lista de tópicos.
- Quantidade de desafios.
- Tópicos concluídos.
- Próximo tópico recomendado.

A organização deve facilitar a identificação de assuntos pendentes.

## 5. Página de estudo

Cada tópico terá uma página individual.

Exemplo: Java Backend → JVM → Garbage Collection.

A página deverá conter:

- Breadcrumb de navegação.
- Título e descrição.
- Objetivos de aprendizado.
- Conteúdo técnico.
- Sumário lateral.
- Blocos de código.
- Diagramas, quando necessários.
- Exemplos práticos.
- Desafios relacionados.
- Pré-requisitos.
- Status do tópico.
- Ação para concluir o estudo.
- Navegação para tópico anterior e próximo.

Quero uma experiência confortável para estudar por períodos prolongados.

## 6. Página de desafios

Crie uma área própria para os desafios.

Apresente:

- Título.
- Enunciado.
- Dificuldade.
- Objetivo.
- Instruções.
- Dicas progressivas.
- Critérios de conclusão.
- Campo para registrar solução.
- Campo para observações.
- Status de resolução.

A solução de referência deve ficar escondida até que eu solicite.

## 7. Página de evolução

Crie uma página que apresente:

- Progresso por etapa.
- Progresso por módulo.
- Tópicos concluídos.
- Desafios resolvidos.
- Histórico de estudos.
- Sequência de dias estudados.
- Tempo de estudo, se registrado.
- Conquistas.

Evite gráficos decorativos. Toda visualização precisa ter utilidade.

## 8. Autenticação

A plataforma deverá possuir login com Google.

Depois de autenticar, o usuário deverá encontrar seus próprios dados e seu progresso.

A experiência precisa ser consistente entre computadores, navegadores e sessões diferentes.

## 9. Responsividade e acessibilidade

Desenvolva pensando principalmente em desktop, mas com boa experiência mobile.

Inclua:
- Navegação responsiva.
- Contraste adequado.
- Estados de foco.
- Feedback das interações.
- Estados de carregamento.
- Estados vazios.
- Mensagens de erro.
- Componentes acessíveis.

## 10. Resultado esperado

Antes de implementar, apresente:

1. Conceito visual.
2. Paleta de cores.
3. Tipografia.
4. Sistema de espaçamento.
5. Componentes principais.
6. Navegação.
7. Wireframes das páginas.
8. Fluxos de usuário.

Depois, implemente as páginas mantendo consistência visual.

Não transforme todas as informações em cards. Utilize hierarquia, tipografia, listas, linhas de progressão, painéis e elementos visuais de maneira equilibrada.

Quero um produto que pareça uma plataforma profissional de aprendizado, com uma experiência visual memorável.
