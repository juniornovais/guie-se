# PROJETO: PLATAFORMA PESSOAL DE ESTUDOS — ROADMAP JAVA BACKEND

Atue como Product Manager, especialista em educação tecnológica e engenheiro de software.

Quero construir uma plataforma pessoal de estudos baseada no meu Roadmap Java Backend.

O objetivo é transformar um roadmap técnico em uma plataforma interativa, na qual eu consiga estudar cada assunto, praticar por meio de desafios, registrar minhas soluções e acompanhar minha evolução ao longo do tempo.

## 1. Contexto e objetivo

Estou estudando para me tornar um desenvolvedor Backend completo, com foco em Java.

Meu roadmap percorre seis grandes áreas:

01 — Fundamentos.
02 — LeetCode.
03 — Backend.
04 — Java Backend.
05 — Sistemas Distribuídos.
06 — System Design.

O roadmap completo foi fornecido junto a este contexto. Ele deve ser tratado como fonte oficial de conteúdo do projeto.

REGRAS IMPORTANTES:

- Não remova nenhum tópico.
- Não substitua assuntos por versões resumidas.
- Não ignore subtópicos.
- Preserve a divisão original em seis etapas.
- Preserve os módulos e suas respectivas descrições.
- Preserve todos os conceitos técnicos.
- Você pode adicionar conteúdos complementares, mas identifique-os como adicionais.
- Não confunda quantidade de conceitos com quantidade de desafios.

## 2. Transformação em estrutura de aprendizado

Converta o roadmap em uma estrutura hierárquica:

Roadmap
  └── Etapa
       └── Módulo
            └── Tópico
                 ├── Objetivos de aprendizagem
                 ├── Conteúdo
                 ├── Exemplos
                 ├── Desafios
                 └── Critérios de conclusão

Cada tópico deve ser uma unidade independente de estudo.

Exemplo:

Etapa: Java Backend
Módulo: JVM
Tópico: Garbage Collection

Objetivos:
- Entender por que existe o Garbage Collector.
- Compreender a relação entre heap e coleta de lixo.
- Conhecer os conceitos de GC Roots.
- Entender o funcionamento da coleta geracional.
- Compreender Stop-the-World.

Conteúdo:
Explicação técnica dividida em seções progressivas.

Exemplos:
Exemplos de código Java, quando aplicável.

Desafios:
Exercícios para aplicar o conhecimento.

Conclusão:
Critérios que comprovem que realmente aprendi o assunto.

## 3. Sistema de desafios

Quero que cada tópico tenha desafios específicos.

Não quero apenas perguntas de múltipla escolha.

Utilize diferentes formatos:

- Questões conceituais.
- Perguntas de entrevista técnica.
- Exercícios de programação.
- Análise de código.
- Identificação de bugs.
- Experimentos práticos.
- Implementações pequenas.
- Projetos progressivos.

Organize a dificuldade em quatro níveis:

Nível 1 — Entendimento:
Verificar se compreendi o conceito.

Nível 2 — Aplicação:
Utilizar o conhecimento em um exercício prático.

Nível 3 — Aprofundamento:
Resolver problemas mais elaborados e entender situações reais.

Nível 4 — Construção:
Desenvolver algo que utilize o conhecimento adquirido.

Exemplo de desafios para Stack e Heap:

1. Explicar a diferença entre stack e heap.
2. Identificar onde objetos e variáveis são armazenados.
3. Criar um programa que demonstre o comportamento da memória.
4. Provocar um StackOverflowError controlado.
5. Analisar um problema de consumo excessivo de memória.

Cada desafio deve ter:
- Enunciado.
- Objetivo.
- Dificuldade.
- Conhecimentos necessários.
- Instruções.
- Critérios de avaliação.
- Resposta ou solução de referência, quando apropriado.

Não revele a solução imediatamente. Quero tentar resolver antes de consultar a resposta.

## 4. Dependências e ordem de aprendizado

Organize os tópicos em uma sequência pedagógica coerente.

Identifique pré-requisitos quando houver dependências reais entre assuntos.

Exemplo:
- Entender memória antes de aprofundar JVM.
- Entender processos e threads antes de estudar concorrência.
- Entender SQL antes de aprofundar transações.
- Entender HTTP antes de estudar APIs e comunicação entre serviços.

Não crie bloqueios artificiais. A plataforma deve recomendar uma ordem ideal, mas permitir explorar outros conteúdos.

## 5. Critérios de conclusão

Um tópico não deve ser considerado concluído simplesmente porque foi aberto.

Quero poder concluir um tópico quando tiver estudado seu conteúdo e realizado os desafios obrigatórios.

Defina critérios de conclusão configuráveis, considerando:
- Leitura do conteúdo.
- Exercícios obrigatórios.
- Desafios práticos.
- Autoavaliação.

Permita que eu marque um tópico como revisado posteriormente.

## 6. Conteúdo educacional

As explicações devem ser tecnicamente corretas, progressivas e aprofundadas.

Quero entender como as tecnologias funcionam internamente.

Evite explicações superficiais como:
"HashMap é uma estrutura que armazena chave e valor."

Quero entender também:
- Como funciona internamente.
- Como é implementado.
- Quais problemas resolve.
- Quais são suas limitações.
- Quais são seus custos computacionais.
- Como é utilizado em sistemas reais.

Apresente:

- Todos os tópicos.
